## 2024-08-26 - String manipulation and array allocation bottleneck in frequent keypress handlers
**Learning:** In a vanilla JS application handling frequent events like keypresses in a calculator app, splitting a string via a regular expression (e.g., `expression.split(/[+\-*/]/)`) creates new arrays and executes expensive RegEx on every keypress. When scanning for a valid decimal insertion point at the end of a long expression, this array allocation creates a small but measurable performance bottleneck and unnecessary garbage collection overhead compared to primitive looping.
**Action:** Always prefer basic primitive looping (like a backward `for` or `while` loop scanning string characters via indexing) instead of allocating arrays (e.g., using `.split()`) or performing repeated regex searches for operations executed in the hot path of frequently fired events.
